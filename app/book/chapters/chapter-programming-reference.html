21  Programming Reference

This course writes its code in one style: the statistical operation gets a name, and a pipeline applies it. Most other R you meet is written the other way, with loops and preallocated vectors—tutorials, answers you find online, code an AI tool hands you, and a few places in the homework. That style is not a mistake and this chapter does not correct it. It gives you the mapping between the two, and wherever the homework shows it, there is a note beside the code saying what the pipeline version of it would be.

Statistical objects in R

The code in this course follows the statistical objects we work with. A population is a vector. A sample is another vector drawn from it. An estimator is a function that takes a sample as its argument.

Populations and samples

Call the population vector y. A sample of size n contains entries drawn from that vector.

draw.sample = function(y, n) {
  J = sample(seq_along(y), size = n, replace = TRUE)
  y[J]
}

Y = draw.sample(y, n)

The population is y; the sample is Y.

Estimators and estimands

An estimator is a function of a sample.

estimator = function(Y) mean(Y)

estimator(Y)

Applying the same function to the population gives the corresponding estimand.

estimator(y)

The function stays the same. The argument tells us whether we are calculating an estimate from a sample or the target in the population.

Repeating and collecting

To apply a function to many objects, repeat the object and map the function over the resulting list.

rep(list(Y), 1000) |> map_vec(estimator)

map_vec() applies estimator to each copy of Y and collects the results in a vector. It handles the storage bookkeeping for us.

Reading a pipeline

The native pipe puts the steps of a computation in reading order. x |> f(y) is the same call as f(x, y).

draw.sample(y, n) |> resample() |> estimator()

Read this from left to right: draw a sample, resample it, and estimate from the result.

The same computation without pipes

The pipe is not doing anything you could not write without it. Here is one computation three ways.

# inside out
estimator(resample(draw.sample(y, n)))

# with a name for each step
Y = draw.sample(y, n)
Ystar = resample(Y)
estimator(Ystar)

# piped
draw.sample(y, n) |> resample() |> estimator()

To read the first one you find the innermost call and work outward. Its words run left to right in the opposite order from the computation: estimator is written first and happens last. The second form fixes the reading order by naming each step, at the cost of two names you have no further use for. The third has the reading order without the names.

The difference grows with the computation. This is the coverage calculation from Part B of the bootstrap homework written inside out.

mean(map_vec(map(rep(list(y), 1000), function(y) draw.sample(y, n)),
             function(Y) {
               interval = interval.estimator(Y)
               interval[1] <= estimator(y) & estimator(y) <= interval[2]
             }))

The first thing that happens, rep, is buried in the middle of the first line, and the last thing, mean, is the first word. The piped version in Interval estimators and coverage is the same four calls in the order they run.

Repeating is looping

map_vec() is a loop. If you have written the loop version of a simulation, you have written this one; the pipeline keeps one of the loop’s three jobs and deletes the other two.

Here is the sampling distribution of the estimator, written as a loop.

theta.hats = numeric(1000)                       # where the answers go
for (b in 1:1000) {                              # step a counter
  theta.hats[b] = estimator(draw.sample(y, n))   # the statistical work
}

Only the third line is statistics. The counter b appears twice and carries no meaning: every repetition draws the same kind of poll, so nothing in the computation depends on which repetition it is. numeric(1000) is a place to put answers.

Delete both and what is left is the course’s form.

theta.hats = rep(list(y), 1000) |>
  map(function(y) draw.sample(y, n)) |>
  map_vec(estimator)

rep(list(y), 1000) is what the loop ran over. map() and map_vec() are the loop.

Which function does which job

What you are doing The function for it
the same thing to each item, keeping every answer map(), map_vec()
combining the answers into one number mean(), sum()
carrying each answer into the next step reduce()
something for its effect, keeping nothing walk(), or a for loop

The first two rows are all our simulations do. The mean(covers) at the end of a coverage calculation is the second row, and keeping it separate from the first is what lets you look at covers before you average it—which is how you find out whether the calculation did what you meant.

Two loops that stay loops

A loop whose step needs the previous step’s answer is not a repetition. The binary search in the calibration homework is one: each step narrows the bracket the step before it produced, so there is no list of independent things to map over. reduce() writes it without the counter, and the state the loop carries is the algorithm rather than bookkeeping.

A loop that keeps nothing has nothing to collect. Printing one plot per sample size runs for its effect; walk() is the same loop under another name.

Sampling and bootstrap distributions

Define resampling as drawing a new sample of the same size from an observed sample.

resample = function(Y) draw.sample(Y, length(Y))

If we had the population, we could approximate the sampling distribution by repeatedly drawing samples from it and calculating the estimator.

sampling.distribution = rep(list(y), 1000) |>
  map(function(y) draw.sample(y, n)) |>
  map_vec(estimator)

Because we do not observe the population, the bootstrap draws from the sample instead.

bootstrap.distribution = rep(list(Y), 1000) |>
  map(resample) |>
  map_vec(estimator)

The two pipelines differ in where their samples come from. That substitution is the bootstrap.

Reproducible random pipelines

End a random pipeline with with_seed() when its result needs to be reproducible.

bootstrap.distribution = rep(list(Y), 1000) |>
  map(resample) |>
  map_vec(estimator) |>
  with_seed()

with_seed() runs the entire upstream expression with the course’s default seed, then restores the random-number state it found. Student-visible uses need no seed argument.

Interval estimators and coverage

An interval estimator is also a function of a sample.

interval.estimator = function(Y) {
  boot.means = rep(list(Y), 1000) |>
    map(resample) |>
    map_vec(mean)
  w = width(boot.means, center = mean(Y))
  c(mean(Y) - w/2, mean(Y) + w/2)
}

interval.estimator(Y)

The course function width(samples, center) returns the width of the interval centered at center that covers the middle 95% of samples.

Coverage repeats the polling procedure and calls the interval estimator once for each poll. The bootstrap inside interval.estimator() stays inside that named function.

covers = rep(list(y), 1000) |>
  map(function(y) draw.sample(y, n)) |>
  map_vec(function(Y) {
    interval = interval.estimator(Y)
    interval[1] <= estimator(y) & estimator(y) <= interval[2]
  })

mean(covers)

Plotting what you simulated

A simulation produces a vector, and a vector is all a plot needs.

bootstrap.distribution = rep(list(Y), 1000) |> map(resample) |> map_vec(estimator)

ggplot() + geom_bar(aes(x = bootstrap.distribution, y = after_stat(prop)))

Three things are going on in that ggplot() call.

+ builds a plot; |> passes a value. ggplot() makes an empty plot and each geom_*() adds a layer to it, so layers are joined with +. The pipe belongs to the computation that produces the numbers, and it stops once the numbers exist. The two operators are not interchangeable and the error message when you swap them does not say so.

aes() says which vector goes where. aes(x = bootstrap.distribution) puts that vector along the horizontal axis. Nothing else has to be arranged first.

after_stat(prop) asks for proportions instead of counts. Without it, geom_bar() plots how many of the 1000 draws landed on each value, and those heights change when you change the number of draws. With it the bars sum to one, which is what makes them comparable with a probability.

That last point is why a simulated distribution and a calculated one can go on the same picture. Each layer names its own vectors, and they share no data.

ggplot() +
  geom_bar(aes(x = bootstrap.distribution, y = after_stat(prop)), alpha = .3) +
  geom_line(aes(x = (0:n)/n, y = dbinom(0:n, n, mean(Y))))

Use geom_bar() when the possible values sit on a grid, as a frequency out of n does, and geom_histogram() when they do not.

When a repetition produces more than one number

map_vec() requires each result to be a single value. When one repetition produces several—an estimate and its width, or two interval estimators you want to compare on the same polls—return a one-row data frame from each repetition and collect them with bind_rows(). Suppose you have written a second interval estimator, normal.interval(), beside the interval.estimator() above.

comparison = rep(list(y), 1000) |>
  map(function(y) draw.sample(y, n)) |>
  map(function(Y) {
    boot = interval.estimator(Y)
    norm = normal.interval(Y)
    data.frame(bootstrap = boot[1] <= estimator(y) & estimator(y) <= boot[2],
               normal    = norm[1] <= estimator(y) & estimator(y) <= norm[2])
  }) |>
  bind_rows()

comparison has one row per poll and one column per quantity. That is the shape to average column by column (mean(comparison$normal)) and the shape ggplot() wants when a plot compares them. Part C of the sample-size homework is this calculation.

Translating other R code

Other R sources often manage repetition with loops, preallocated vectors, or the apply family. In this course, translate those forms into a pipeline that names the statistical function being repeated.

Elsewhere In this course
preallocate a vector, then fill it in a for loop repeat the input, then use map_vec()
replicate(B, expression) repeat the input, then map a named function
sapply(xs, f) map_vec(xs, f)
lapply(xs, f) map(xs, f)

For example, this imperative computation

boot.means = numeric(B)
for (b in seq_len(B)) {
  boot.means[b] = estimator(resample(Y))
}

becomes

boot.means = rep(list(Y), B) |>
  map(resample) |>
  map_vec(estimator)

Both perform the same statistical operation. The pipeline leaves the storage bookkeeping to R and keeps the sample, resampling step, and estimator visible.

The same computation in Python

The syllabus asks for programming experience rather than R experience. If the language you have is Python, these are the forms this course uses and what each one is there.

In this course In Python
y[J] y[J], with a NumPy array
seq_along(y) range(len(y))
mean(Y) Y.mean()
sample(seq_along(y), n, replace = TRUE) rng.integers(0, len(y), n)
function(Y) mean(Y) lambda Y: Y.mean(), or a def
map(xs, f) [f(x) for x in xs]
map_vec(xs, f) np.array([f(x) for x in xs])
rep(list(Y), B) \|> map_vec(f) np.array([f(Y) for _ in range(B)])
x \|> f(y) f(x, y)
bind_rows() pd.DataFrame(records)

Three of the differences are not vocabulary.

A list comprehension is this course’s map. [f(x) for x in xs] and map(xs, f) are the same operation, and [f(Y) for _ in range(B)] discards its counter for the same reason Repeating is looping does. If you know comprehensions, the pattern this course is built on is one you already use.

Python has no pipe. f(g(h(x))) is the inside-out form from The same computation without pipes, and Python’s usual answer to it is the method chain x.h().g().f(), which reads left to right for the same reason the pipe does.

R counts from one and Python counts from zero. y[1] is the first entry in R and the second in Python, and 1:n covers the same entries as range(n). This is the difference that produces wrong answers rather than error messages, so it is worth checking first when a translated calculation is off by a little.

Plotting is the one place with no close correspondence. matplotlib builds a picture by calling methods on an axes object rather than by adding layers to a value, so Plotting what you simulated is worth reading even if you have plotted before.
